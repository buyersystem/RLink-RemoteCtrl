# RLink 内容感知串流与接收端超分实施方案

现行版本：2026-10-06。本文只描述当前方案；历史网络恢复修复、失败项和测试日志保留在[问题记录](../架构/问题记录/2026-10-05-屏幕串流码率保护与FPS恢复问题记录.md)。完整组件设计见[架构方案](../架构/内容感知串流与超分完整方案.md)。

## 1. 本次方案收敛

内容感知只根据已确认场景平滑调整网络波动画质取舍系数 `k`。原场景分辨率、FPS、码率候选搜索、参考需求曲线、模型校准、执行门控、档位驻留和独立恢复控制已撤销，不再作为当前设计保留。

主链路是：

```text
屏幕低频采样 → 远程视觉大模型 → 已确认场景
    → 独立 SceneQualityCoefficientSmoother
    → 动态 k → 现有编码画质保护 → WebRTC 原生丢帧 / GoogCC / 恢复
```

正常网络不因场景主动改变画面。用户选择的采集 FPS、发送分辨率/FPS 上限、视频码率上限和连接参考上限保持现有行为；场景输出不调用 RTP SetParameters、SetBitrate，不重启编码器或带宽估计，不增加探测。

## 2. 场景与系数

范围是可维护的场景配置；目标取范围中点，不根据带宽、QP、运动量在范围内另行选择。

| 返回场景 | 显示名称 | 范围 | 中点目标 |
|---|---|---:|---:|
| `code_terminal` | 代码 / 终端 | 0.15～0.35 | 0.25 |
| `document` | 文档 / 阅读 | 0.15～0.35 | 0.25 |
| `spreadsheet` | 表格 / 报表 | 0.15～0.35 | 0.25 |
| `web_app` | 网页 / 普通软件 | 0.35～0.65 | 0.50 |
| `photo_graphics` | 图片 / 图形编辑 | 0.10～0.30 | 0.20 |
| `cad_diagram` | CAD / 示意图 | 0.15～0.35 | 0.25 |
| `video` | 视频播放 | 0.60～0.80 | 0.70 |
| `game_3d` | 游戏 / 实时三维 | 0.70～0.90 | 0.80 |
| `mixed` | 混合内容 | 0.35～0.65 | 0.50 |

系数越小越保每帧清晰度，越大允许画质承担更多带宽缺口、更偏向保持 FPS。它不对应固定 FPS，不保证固定 QP 或实际发送码率；这些范围是首版体验基准。

## 3. 独立平滑器

`media_intelligence/core/SceneQualityCoefficientSmoother` 只依赖标准 C++20 与场景枚举，不依赖 Qt、WebRTC、采集器、网络、Windows、线程或系统计时器。宿主提供单调毫秒时间并串行调用。

公开操作为 `Reset(initialK, now)`、`SetScene(scene, now)`、`SetTarget(k, now)`、`Evaluate(now)`；诊断可读取场景、范围、目标及剩余时间。`SetTarget` 用于宿主明确要求的手动回退，不承担识别或网络判断。

默认线性过渡 1000 ms：

```text
p = clamp((now − startTime) / 1000 ms, 0, 1)
k = startK + (targetK − startK) × p
```

新场景先求当时实际值，再作为新过渡起点；同一场景或相同目标不重启过渡。中途改目标连续，延迟调用直接按实际时间推进，不补跑计时帧。输出限制在 0～1，内部保留浮点精度；编码发布时四舍五入为百分位整数，仅变化时写入原子配置。未知场景本身不更改平滑器目标。

## 4. 宿主、关闭和结果过期

原有会话统计线程每 50 ms 轻量 tick 平滑器，正式 `GetStats` 仍约每秒一次；不新增线程，不提高 WebRTC 统计请求频率。编码线程直接读取既有原子百分位系数，不等待统计锁或分析结果。

用户手动系数独立持久化，范围 0.00～1.00、最多两位小数，默认 0.50。自动场景输出不覆盖此设置。开启时以当前手动系数初始化；关闭内容感知后立即恢复手动值，不等待一秒。自动期间修改手动值更新回退基准，不强制覆盖仍然有效的场景目标。

采用场景的时间来自真实完成并被确认的模型结果；周期性读取同一快照不能刷新这个时间。场景有效期为：

```text
maximumSceneAge = max(15 秒, 3 × API 请求间隔 + 请求超时)
```

未知结果、低置信度、短时失败先保持旧场景。超过有效期后由宿主调用 `SetTarget(manualK, now)`，用 1000 ms 平滑回到手动系数。会话 generation 和配置/模式变化隔离旧结果，不允许晚到响应恢复前一会话场景。

## 5. 现有画质保护与恢复

在既有网络保护路径内、有效视频目标预算 `B > 0` 且未折扣参考 `A > B` 时：

```text
C = A − (A − B) × k
```

`A` 是未递归折扣的名义画质参考；`B` 使用 WebRTC 视频目标分配，不能混同编码器修正后的分配；`C` 只交给统一编码器包装层。原生 FrameDropper、拥塞控制和 pacer 继续服从真实预算。零预算保持暂停；未进入保护或 `A ≤ B` 时遵循既有正常路径。

内容感知开启与关闭共用已修复的恢复机制，不重置健康历史、额外启动探测或等待场景平滑结束。核心不会承诺立即发现网络恢复；原生反馈与探测守卫仍然有效。具体恢复实现和已有实测边界以问题记录为准。

视频上限仍由用户分辨率 × 目标 FPS × 视频上限系数计算，默认 bpp 0.15、范围 0.03～0.50，无固定 4 Mbps 下限；连接参考上限内部保留视频上限的 1.05 倍。此 bpp 与波动系数 k 是不同参数。

## 6. API、截图与诊断

已接入可复用 OpenAI-compatible Chat Completions 视觉组件；provider 预设不代表模型必定支持图片，需测试用户填写的真实端点和模型。本轮不重新认证任何第三方模型能力。

响应分类只允许上述九个场景及有限的 `[0,1]` 置信度。确认规则沿用：低于 0.70 不切换；新场景达到 0.85 可单次采用；中等置信度需两次连续一致；当前场景的可信重复结果更新时间。所有请求间隔采用相同规则。静止转运动、IDE 滚动或窗口内画面变化不能直接替代语义场景。

请求间隔默认 1 秒，可选 0.5、1、2、5、10、20、30、60 秒；超时默认 8 秒。最长边默认 1280 像素、JPEG 质量默认 60，可在设置调整，连接/截图测试与实际远控共用。缩放转换和 TurboJPEG 编码在低频分析工作线程完成；正式远控直接压缩 I420，不把编码任务放入采集、GUI 或编码热路径。

最多一个在途请求与一个待处理最新样本；失败退避、熔断和取消沿用既有运行时。截图、JPEG、请求数据驻留内存，用完释放，不保存屏幕截图文件。自动连接测试使用合成图；只有用户主动截图测试才取当前画面。

API 密钥通过 Windows 当前用户 DPAPI 保存，不写配置、日志或诊断。远程上传要求用户选择 API 模式并同意缩略图/费用提示；默认模式不上传。关闭、暂停、清除密钥或配置失效时停止上传并取消可取消的请求。协议只接收分类值，图中指令与模型文本不参与程序执行。地址校验、正常 TLS 校验和响应限额继续保留。

“视觉分析性能”保留缩放转换耗时、JPEG 编码耗时、JPEG KB、最近原始分类与年龄。“内容策略观察”只保留采用场景、范围、中点目标、当前实际系数、手动基准、剩余时间和状态；删去旧预算/候选/门槛/执行卡。原生网络与编解码诊断保留在其原页面。

## 7. 本地模型与 VSR 边界

本地 MobileNetV3 + Windows ML 仍为后续任务，当前本地规则只观察运动，不提供上述细场景分类。API 失败不会伪装为本地语义成功，也不会自动把本地模式切为云端。CLIP 不在本方案范围内。

接收端 NVIDIA RTX Video VSR 仍为待实现后端：使用本地 `third_party/vsr` SDK、硬件能力通过后设置才允许启用。初始化、处理和释放放在现有 D3D11 presentation 工作线程；与发送端平滑器独立，不能为了调用 VSR 主动降低发送分辨率。准确接口、纹理和回退要求见架构方案。

## 8. 验证与完成边界

2026-10-06 Release 客户端构建及以下回归通过：核心平滑器、真实 RTP sender 接入、生产统计调度、原生画质/丢帧恢复、NVENC 编码、GoogCC 透传、用户视频上限、API 协议与本机 HTTP 适配、用户规格协议、采集计时器。界面预览六项断言通过，Windows Qt 平台生成的浅色、深色与过渡截图已检查。

最终构建日志为 `build/scene-smoothing-final-build.log`；主要行为证据为 `scene-smoothing-core-test.log`、`scene-smoothing-integration-test.log`、`scene-smoothing-poller-test.log`、`scene-smoothing-native-quality-test.log`、`scene-smoothing-nvenc-quality-test.log`、`scene-smoothing-vision-adapters-test.log` 和 `scene-smoothing-ui-preview.log`，均位于本机 build 目录。真实 sender 测试未协商媒体或发送网络数据；NVENC 回归使用受控预算与原生 FrameDropper，不能解释为双机限速实测。

本次验证覆盖：

1. 九场景范围/中点、连续切换、相同目标、单调时间和 1000 ms 过渡。
2. 50 ms tick 与约 1 秒 GetStats 分离、过期按真实模型时间、手动独立保存及关闭即时回退。
3. 场景切换只更改原子 k，不触发采集/RTP/码率上限重配、编码器重启或 BWE 重置；正常网络体验与既有恢复保持。
4. 关闭、未知、过期、配置变化、晚到回包以及多连接隔离。
5. 单卡诊断与视觉性能页面、浅色/深色布局、旧策略代码及测试引用清理。

双机 NetLimiter 长短限速、远端真实呈现和第三方 API 实网体验仍需运行验证；AMD/Intel 硬件和 VSR 不得用 NVENC/本机测试代替验收。
